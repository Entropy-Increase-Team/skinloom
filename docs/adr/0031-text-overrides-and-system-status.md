# 0031 翻译覆盖放在设置里；系统状态页

- 状态：已接受（2026-10-31）
- 相关：设计文档 02 F39、F40、§5；04 §3.4、§5.1；ADR 0029

## 背景
M4 第三部分（ADR 0029）是翻译覆盖与系统状态：
- BS 的 `language_lines` 表让站长按 group/key 改写任意语言的文字。04 §5.1 规划了 `translation_overrides` 表，02 §5 也写了 `language_lines → translation_overrides` 的迁移映射。
- BS 的状态页列出版本、环境、数据库连接信息（含数据库用户名）和已启用的插件。02 F40 要求加上健康检查、队列、存储、缓存的状态，而且不显示数据库用户名。

## 决策
- **翻译覆盖不建表，放在设置 `i18n.overrides` 里**：`{"zh-CN": {"nav.skinlib": "…"}, "en": {…}}`，按消息键。
  - 设置已经能热加载到所有节点和已打开的页面，修改也写进审计日志。改写的文字通常只有几十条，单独建表还要给三种数据库各写一份迁移，换不来什么。
  - 上限 3000 条，键名最长 200 个字符，文字最长 2000 个字符。花括号必须成对：不成对的文字会让消息格式解析失败。
  - 02 §5 的迁移映射相应改为 `language_lines → i18n.overrides`（M5 的导入器做）。
- **前端套用**：bootstrap 带上访客语言的那一份（`messages`），next-intl 的请求配置把它覆盖到自带的消息上。
  - 只替换已经存在的文字。键名写错，或者改版后消息被删了，都只是不生效，不会报错。
  - 覆盖时复制沿途的对象，不修改所有请求共享的消息模块。
- **翻译页** `/admin/translations`：服务端读出各语言的原文交给编辑器，可以按键名或文字搜索。改写的文字必须保留原文的占位符（`{site}` 这类，由页面填入实际内容）。占位符不一致或花括号不成对时不能保存。
- **只覆盖网页界面的文字**：邮件、兼容 BS 的接口提示、Yggdrasil 的错误信息由后端生成，暂不在这里改写，等后端也接入消息目录时再做。
- **系统状态** `GET /api/v1/admin/status` 与页面 `/admin/status`：
  - 服务端：版本、提交、构建时间、Go 版本、系统与架构、`server.role`、`web.mode`、启动时间；
  - 数据库：类型与服务器版本、已执行的迁移版本、未执行的迁移数、响应时间。不显示连接串、用户名或文件路径；
  - 材质存储：local 或 s3、文件数与占用空间；
  - 后台任务：等待中、超时一分钟以上、已失败（保留 7 天）、最早超时的任务；
  - 邮件：发送方式，验证与找回密码是否可用；
  - 配置：配置版本、当前主题、改过的设置数。插件要到第二阶段。
- **检查结果**：数据库、迁移、任务超时、任务失败、邮件、站点地址，每项 ok、warn 或 error，前端按 id 显示对应的说明。数据库连不上时，只返回服务端信息和这一项。
- 数据由各自的模块提供：`db.ServerVersion`、`migrate.Status`、`jobs.Counts`、`stats.Storage`（后台概览也用它）。接口只负责汇总。
- **只看当前节点**：多实例部署时，请求落到哪个实例就显示哪个实例的版本与启动时间。数据库、任务与存储是共享的，各实例看到的一样。

## 影响
- 新设置 `i18n.overrides`；bootstrap 增加 `messages`；新接口 `getSystemStatus`。没有新表与迁移。
- `httpapi.Deps` 增加 `Runtime`（启动时间、角色、前端模式、存储方式），由 `app.Run` 填写。
