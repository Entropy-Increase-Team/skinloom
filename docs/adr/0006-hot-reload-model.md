# 0006 热加载模型

- 状态：已接受（2026-10-23）
- 相关：设计文档 04 §7；05 §9

## 决策
- **配置版本号**：`system_state.config_version`，设置、主题、插件任何变化都在同一事务里递增。
- **原子替换**：设置快照、主题注册表、Hook 表、路由/菜单等都是 copy-on-write，按"贡献者"（owner）整体替换；请求开始取一次快照，请求内一致。
- **跨进程/跨节点**：每个节点每 2 秒轮询版本号（CLI 改设置、其它副本改设置都能被感知）；引入 Redis 后改为订阅，接口不变。
- **浏览器**：`/events` SSE 推送 `config.changed`，页面 `router.refresh()`，不整页刷新。
- **文件配置**：监听配置文件所在目录（编辑器"原子保存"会替换文件，监听文件本身会丢失监听——M0 已踩坑，koanf 自带的 watcher 因此弃用）；热键即时生效（日志、限流、可信代理、Next.js 进程参数——端口改动会重启前端子进程），冷键（监听地址、数据库、数据目录）只提示需要重启。
- 配置文件写错时保留运行中的配置并记录错误，不会让站点挂掉。

## 影响
- 所有可热替换对象禁止在请求外被长期持有引用。
- 插件安装/升级/卸载在 P2 复用同一机制。
