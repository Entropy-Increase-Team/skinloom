# 从 Blessing Skin 迁移

`skinloom import bs` 把一个 Blessing Skin（BS）站点导入全新的 SkinLoom。BS 的数据库只读不写，随时可以切回去。

## 会带过来什么

| 内容 | 说明 |
|---|---|
| 账号 | 邮箱、昵称、积分、权限（封禁、管理员、超级管理员）、邮箱是否已验证、注册 IP 和时间 |
| 密码 | 原来的密码照常能登录。BS 的全部算法（BCRYPT、ARGON2I、MD5、SHA256、SHA512 及加盐的版本）都认得，启用了 password-algorithm-transition 插件的站点按 `PASSWORD_METHODS` 和对应的盐逐个识别。首次登录后自动升级为 argon2id |
| 角色 | 名字、皮肤、披风，以及 Yggdrasil 插件分配的 UUID：进服后背包、领地等按 UUID 存的数据都还在 |
| 材质 | ID、名字、类型、公开或私有、上传者、上传时间，以及文件本身。文件名就是 hash，链接不变；只有上传后被改过内容的文件按新内容的 hash 保存，它的皮肤地址会变 |
| 衣柜 | 收藏的材质和自己起的名字；收藏数按衣柜重新计算 |
| 举报、通知 | 全部举报；只有未读的通知 |

**不会带过来**：网页登录状态、启动器令牌、第三方应用的授权，所有人重新登录一次即可。

**这一版还没有**：站点设置、翻译覆盖、OAuth 应用、Yggdrasil 签名密钥，会在下一版加上。在那之前：
- 导入后到后台重新填写站点名称、邮件等设置。
- 用 authlib-injector 的游戏服务器在切换后重启一次，才会取到新的签名公钥。

材质、角色、用户的 ID 都与 BS 相同，所以 `/skinlib/show/123` 这类链接和游戏里的皮肤地址都不用改。

## 步骤

1. **准备一个全新的 SkinLoom**，按 [部署](overview.md) 装好，但**先不要打开安装页面**：导入会带来 BS 的超级管理员。已经启动过也没关系，只要还没创建账号，导入前先停掉即可。
2. **BS 开启维护模式**，或者至少停止注册和上传。导入在一个一致的快照里读数据，BS 不停也能导，但之后的改动不会跟过来。
3. **试运行**。下面的路径换成 BS 网站的目录：

   ```bash
   skinloom import bs --env /var/www/blessing-skin/.env --dry-run
   ```

   导入器从 `.env` 读出数据库连接、表前缀、密码算法和盐。材质默认从 BS 的 `storage/textures` 读。
   - 用了 OSS、COS、七牛等存储插件的站点，先把材质下载到一个目录，再加上 `--textures 目录`。
   - BS 在别的服务器上时，直接指定连接，并把 `storage/textures` 复制过来。连接串里有密码，放在环境变量 `SKINLOOM_BS_DSN` 里，不要写在命令行上（会留在 shell 历史和进程列表里）；盐同理用 `SKINLOOM_BS_SALT`：

     ```bash
     export SKINLOOM_BS_DSN='用户:密码@tcp(主机:3306)/数据库'
     skinloom import bs --driver mysql --textures ./textures --dry-run
     ```

   - 建议给导入用一个只读的数据库账号。

4. **看报告**。控制台显示前 40 行，完整报告写在 `data/import/` 下。条目分四类：

   | 类别 | 含义 | 要做什么 |
   |---|---|---|
   | BLOCKING（阻止） | 需要人来决定的冲突，比如两个账号的邮箱只差大小写 | 在 BS 后台改掉，再试运行 |
   | WARNING（警告） | 导入了，但有东西和以前不一样，比如材质文件缺失、密码格式不认识 | 能补的补上（比如把文件放回材质目录）；认不出密码的用户要用邮件重设 |
   | FIXED（已修正） | 按默认规则改过，比如重名的角色加了 `_2`、指向已删除材质的皮肤被清空 | 看一遍即可 |
   | DROPPED（已丢弃） | 没有导入，比如主人已不存在的角色、衣柜里重复的条目 | 看一遍即可 |

   试运行和正式导入做的是完全相同的事情，只是最后撤销，所以报告也一样。

5. **正式导入**：去掉 `--dry-run` 再执行一次。全部写入在一个事务里，中途出错不会留下半个站点；失败时报告照样写出，开头写明原因，修好后重新执行即可。
6. **启动 SkinLoom**，用 BS 的超级管理员账号登录。抽查几个账号、皮肤库，再用启动器实际进一次服。
7. **切换**反向代理或域名到 SkinLoom。所有地址都兼容，玩家和游戏服务器不用改配置。
8. **回滚**：BS 的数据库从未被写入，切回 BS 即可。材质目录与 BS 共用时见下文。

## 默认的处理规则

| 情况 | 处理 |
|---|---|
| 两个账号的邮箱只差大小写，或账号没有邮箱 | 阻止导入：SkinLoom 的邮箱不区分大小写 |
| 角色名重复（不区分大小写）或超过 32 个字符 | 最早的保留，其余改为 `名字_2`、`名字_3`……，并给主人发一条站内通知 |
| 同一用户把同一个文件上传了两次 | 合并到最早的那个，衣柜和角色都改指过去 |
| 皮肤或披风指向已删除的材质，或皮肤放在了披风的位置 | 清空 |
| 材质的上传者已注销 | 保留材质，显示为已注销用户 |
| 材质文件和文件名（hash）对不上 | 按文件内容的 hash 保存 |
| 材质文件缺失 | 材质照样导入，访问时返回 404（和 BS 一样）。找回文件后，按报告里写的名字放进 SkinLoom 的材质目录即可，不用重新导入 |
| 衣柜里重复的条目 | 只留一条 |
| 衣柜里指向不存在的材质或用户的条目 | 丢弃 |
| 同一人对同一材质的重复举报 | 只留最早的一条 |
| 文字里有无效的 UTF-8 或 NUL 字符 | 去掉 NUL，无效的字节换成 `�` |

## 材质文件放在哪

导入会把文件复制进 SkinLoom 的材质目录（默认 `data/textures`）或 S3，需要同样多的磁盘空间。**推荐这样做**：BS 的目录保持原样，随时可以切回去。

空间实在不够时，可以在导入前把 BS 的目录挂到 `data/textures` 上（Linux：`mount --bind /var/www/blessing-skin/storage/textures data/textures`），导入发现是同一个目录，就只复制内容被改过的文件。用挂载而不是符号链接：系统服务只允许写 `data/` 之下的路径，符号链接指向的目录写不进去。

共用目录之后，SkinLoom 把这个目录当成自己的：
- 定期清理会删掉没有材质用到的文件，包括 BS 里那些没有导入的材质（比如类型未知）的文件，以及被改过内容的文件的原文件。
- 在 SkinLoom 里删除材质会删掉它的文件，BS 那边的同一个材质随之失效。

所以共用之前先备份 BS 的材质目录，回滚时用备份。

## 常见问题

- **"the SkinLoom database already has users or textures"**：只能导入到没有账号的新站点。如果已经在安装页面建了管理员，删掉 `data/` 重新开始；用 MySQL、PostgreSQL 的，换一个空库。
- **BS 改过时区**：BS 按 `config/app.php` 的时区记录时间，默认 `Asia/Shanghai`。改过的话加上 `--timezone 时区名`。
- **导入成功后还想重来**：换一个空库（SQLite 就是删掉 `data/skinloom.db`）再导入。导入不会和已有的数据合并。
