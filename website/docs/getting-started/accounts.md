# 账号与用户管理

注册、登录、验证码与邮件的设置，用户自己能做什么，以及管理员如何管理用户。

## 第一个管理员

站点第一次启动时，日志里会打印一次性安装链接（`/setup?token=…`）。用它设置站点名称与地址并创建**超级管理员**。安装完成之前，注册入口是关闭的：第一个账号只能来自安装页。见 [快速开始](quick-start.md#启动之后)。

## 注册

- `auth.registration`：`open`（默认）任何人都可以在 `/auth/register` 注册；`closed` 关闭注册，页头与首页的"注册"按钮随之隐藏，注册接口返回 403。
- `auth.registrations_per_ip`：同一地址 24 小时内最多注册几个账号（默认 3，`0` 不限）。按精确地址在数据库里计数（重启后仍然有效），IPv6 另外按 /64 计数，换一个同网段地址绕不过去。放在反向代理后面时，务必配置[可信代理](../deployment/reverse-proxy.md)，否则所有人都会被算成代理的地址。
- 新账号获得 `score.initial` 积分（默认 1000），注册后自动登录。
- 邮箱不区分大小写，同一邮箱只能注册一次；密码 8–128 个字符；昵称 1–32 个字符。

## 邮件

邮箱验证和找回密码都需要先配置邮件，并设置站点地址 `site.url`（安装向导会自动填写）：邮件里的链接只用它生成，绝不使用访问者请求里的地址，否则任何人都能让站点发出一封真实的重置邮件、链接却指向自己的服务器。没有设置 `site.url` 时，这两项功能不可用。

以 QQ 邮箱为例（在邮箱设置里开启 SMTP 并生成授权码）：

```bash
skinloom settings set mail.from '"云织 <你的号码@qq.com>"'
skinloom settings set mail.smtp.host '"smtp.qq.com"'
skinloom settings set mail.smtp.port 465
skinloom settings set mail.smtp.encryption '"tls"'
skinloom settings set mail.smtp.username '"你的号码@qq.com"'
skinloom settings set mail.smtp.password '"授权码"'
skinloom settings set mail.driver '"smtp"'
```

163、Gmail、Outlook、企业邮箱同理：465 端口用 `tls`，587 端口用 `starttls`。配置好之后，管理员可以调用 `POST /api/v1/admin/mail/test` 发一封测试邮件；失败时会直接返回 SMTP 服务器的错误信息（只给管理员看）。开发时可以用 `mail.driver = log`，邮件内容会写进服务端日志而不是真的发出去。

邮件在后台发送：注册、找回密码的请求不会因为邮件服务器慢而卡住；发送失败会在 1 分钟、5 分钟、15 分钟、1 小时后重试，仍然失败就放弃并在日志里告警。邮件发出（或放弃）后，数据库里的邮件内容（含一次性链接）随即清除。

## 邮箱验证

配置邮件后，新注册的账号会收到一封验证邮件。链接 24 小时有效、只能使用一次；打开链接后需要点击"确认验证邮箱"才会生效（邮件安全软件预先打开链接不会把它用掉）。没有验证的用户登录后，页面顶部会提示并提供"重新发送"（每分钟 1 封、每天最多 5 封，新链接发出后旧链接作废）。

## 找回密码

登录页的"忘记密码？"（配置邮件后才显示）进入 `/auth/forgot`。无论邮箱是否注册过，页面都显示同样的提示，不能用来探测账号是否存在。

- 需要先完成验证码；同一地址每小时 10 次、同一邮箱每小时 3 次（对未注册的邮箱同样计数）。
- 重置链接 30 分钟有效、只能使用一次，新链接发出后旧链接作废。
- 设置新密码后，该账号在**所有设备**上的登录都会失效（Blessing Skin 不会这样做，S02）；邮箱同时视为已验证。

## 登录保护

- 登录失败一律提示"邮箱或密码不正确"，不会透露账号是否存在。
- 同一客户端对同一账号失败 `auth.login_captcha_after` 次（默认 3）后，需要先完成验证码。
- 硬性上限（每 15 分钟）：同一地址 50 次、同一地址对同一账号 10 次，超过后返回 429。
- 同一账号在所有地址上合计失败 20 次后，**所有人**登录该账号都需要验证码，但不会锁定账号：攻击者无法借此把真正的用户（包括管理员）挡在门外。未启用验证码（`captcha.provider = none`）时，改为合计 100 次后暂时锁定。

## 验证码

验证码用在注册和多次登录失败之后。切换提供方即时生效，不需要重启：

```bash
skinloom settings set captcha.provider '"turnstile"'
skinloom settings set captcha.turnstile.site_key '"0x4AAAA…"'
skinloom settings set captcha.turnstile.secret_key '"0x4AAAA…"'
```

| `captcha.provider` | 说明 | 中国大陆访问 |
|---|---|---|
| `image`（默认） | 内置图形验证码：5 个字符，旋转、扭曲、干扰线。不依赖任何第三方服务 | ✅ |
| `turnstile` | [Cloudflare Turnstile](https://www.cloudflare.com/products/turnstile/)：多数情况下无需操作，免费 | 一般可用 |
| `recaptcha` | Google reCAPTCHA v2（复选框）：脚本与校验都走 `recaptcha.net` | 一般可用 |
| `hcaptcha` | [hCaptcha](https://www.hcaptcha.com/) | 一般可用 |
| `none` | 关闭验证码（不建议在公网开放注册时使用） | — |

第三方验证码需要在对应平台创建站点，取得 **site key**（公开，发给浏览器）与 **secret key**（只保存在服务端，永远不会出现在页面或接口里），分别填入 `captcha.<提供方>.site_key` 与 `captcha.<提供方>.secret_key`。

说明：

- 每个图形验证码只能尝试一次，无论对错都会作废，5 分钟过期，无法暴力猜测。它保存在后端进程的内存里：后端有多个副本时，请改用第三方验证码，或让同一访客固定访问同一副本。
- 第三方服务暂时无法访问、或密钥配置错误时，表单会提示"验证码服务暂时不可用"，并在服务端日志里告警（不会因此放行）。
- 填错其它字段（如密码太短）时，表单不会消耗验证码。

## 用户中心与签到

登录后点击页头的"用户中心"进入 `/user`：显示积分、角色数、衣柜里的材质数、上传的材质数与占用空间、站点公告，以及角色、衣柜、上传、皮肤库、个人资料的入口。

**签到**：每次随机获得 `score.sign_min`–`score.sign_max` 积分（默认 10–100）。默认距离上次签到满 `score.sign_gap_hours` 小时（默认 24）后才能再签；开启 `score.sign_daily` 后改为每天一次，在站点时区 `site.timezone`（默认 `Asia/Shanghai`）的零点刷新。还没到时间时按钮不可点，并显示下次可签到的时间。同时点很多次也只会成功一次（Blessing Skin 会多次得分，C03）。

## 通知与头像

- **通知**：页头的铃铛显示未读数量，点进 `/user/notifications` 查看；点开一条即标为已读，也可以"全部标为已读"。正文是 Markdown（链接、列表、加粗等），HTML 和脚本链接不会生效。
- 管理员在后台概览的"发送通知"里，可以发给所有用户、只发给普通用户（不含管理员），或按用户 ID、邮箱发给一个人。发给多人时只写一条记录，每个用户下次打开通知时收到自己的一份；之后注册的用户不会收到（与 Blessing Skin 相同）。发送记入审计日志 `admin.notification_sent`。
- **头像**：在衣柜里给皮肤点"设为头像"（也可以是皮肤库里任何你看得到的皮肤），页头和个人资料页显示它的头部，地址是 `/avatar/user/<你的 ID>`。个人资料页可以移除头像。这个皮肤以后被删除，头像自动清空；变成别人的私有材质时，别人看到的是灰色占位头像。
- 站点公告（`site.announcement`）同样按 Markdown 显示。

## 个人资料与登录设备

登录后点击页头的昵称进入 `/user/profile`：

- **昵称与语言**：语言可以选"跟随浏览器"或站点提供的语言，同时决定站点发给你的邮件用什么语言。
- **修改密码**：需要当前密码（通过[第三方登录](./social-login.md)创建、还没有密码的账号在这里设置第一个密码，不需要）。改完之后，除了正在使用的这台设备，其它设备上的登录全部失效。
- **修改邮箱**：需要当前密码。旧邮箱会收到一封变更通知，新邮箱需要重新验证；其它设备同样会退出登录。
- **登录设备**：列出账号在哪些设备上登录（浏览器、地址、最近活跃时间），可以单独退出某个设备，或一键退出其它所有设备。怀疑账号被盗时先改密码，再看这里。
- **游戏启动器**：外置登录的接口地址，以及有几个启动器登录着账号，可以一键全部退出（见[外置登录](./launchers.md)）。改密码、退出其它所有设备时启动器也会一起退出。
- **应用与令牌**（用户中心入口，`/user/oauth/manage`）：注册自己开发的应用、撤销允许过的应用、创建个人访问令牌，见[开放平台](./open-platform.md)。改密码、退出其它所有设备时，应用的令牌和个人访问令牌也会失效。

密码确认在 15 分钟内最多错 5 次，之后需要稍等再试。密码管理器的"修改密码"功能会通过 `/.well-known/change-password` 直接打开这个页面。

## 注销账号

在个人资料页底部输入当前密码即可注销，账号立即在所有设备上退出登录。

- **30 天内**用原来的邮箱和密码登录，账号就会恢复，资料不会丢失；管理员也可以在后台把状态改回"正常"来恢复。
- **30 天后**账号被永久删除（后台每小时检查一次），这个邮箱可以重新注册。
- 管理员和超级管理员不能注销自己的账号，需要先由超级管理员降级为普通用户。

## 角色与后台用户管理

| 角色 | 能做什么 |
|---|---|
| 普通用户 | 使用站点 |
| 管理员 | 进入后台；管理**普通用户**（改昵称、邮箱、积分、验证状态、密码，封禁，删除）和他们的角色；处理举报；修改站点设置；查看审计日志 |
| 超级管理员 | 管理员的全部权限；管理所有人，包括其它管理员；修改角色 |

管理员点击页头的角色徽章进入后台概览 `/admin`。用户管理在 `/admin/users`，可以按邮箱、昵称或用户 ID 搜索，按角色、状态筛选。几条规则：

- 封禁用户或为他设置新密码后，他在所有设备上立即退出登录；被封禁的账号无法登录。
- 给用户换了邮箱后，新邮箱默认是"未验证"，可以在同一次保存里手动勾选"邮箱已验证"。
- 不能修改自己的角色或状态，也不能在后台删除自己；超级管理员要先降级才能被删除。
- 站点至少保留一个正常状态的超级管理员：最后一个超级管理员不能被降级或封禁。
- 后台删除是**立即、永久**的（没有 30 天宽限期），相关记录只在审计日志里保留邮箱和昵称。

脚本可以用 `admin.token` 调用同样的接口（`/api/v1/admin/users`），它拥有超级管理员的权限。

## 后台概览、角色与举报

- **概览** `/admin`：用户、角色、材质（含公开数）、衣柜条目、存储（文件数与总大小，相同的图片只算一份）和待处理举报的总数，以及最近 31 天每天的注册数与上传数（按站点时区 `site.timezone` 划分日期）。柱状图上悬停或用键盘聚焦可以看到当天的数值，也可以展开成表格。
- **角色** `/admin/players`：按角色名开头、UUID（带不带连字符都可以）或角色 ID 搜索；用户管理里每一行的"角色"可以直接查看这个用户的全部角色。可以改名（遵守角色名规则，v3 UUID 随名字变化）、转移给其他用户（新主人衣柜里没有的皮肤和披风会被脱下）、换皮肤与披风（填材质 ID，必须在角色主人的衣柜里、类型正确）、删除（按 `score.return_on_delete` 退还创建费用）。权限与用户管理相同：管理员管理普通用户和自己的角色，超级管理员管理所有人的。
- **衣柜管理**只有接口（与 Blessing Skin 相同）：`GET/POST /api/v1/admin/users/{id}/closet`、`DELETE /api/v1/admin/users/{id}/closet/{textureId}`。管理员放进去的材质不收费，上传者也不得收藏奖励。
- **举报** `/admin/reports`：默认显示待处理的举报，也可以查看已处理、已驳回的。每条举报可以：
  - **删除材质**：收藏它的用户退还积分，举报者拿回举报费并获得 `score.reporter_reward`；同一个材质的其它待处理举报一起结案（退还举报费，不再奖励）。材质如果已经被上传者删掉，按钮变成"标记已处理"，只退举报费。
  - **封禁上传者**：与在用户管理里封禁相同（管理员只能封禁普通用户），对方立即在所有设备上退出登录；举报者同样退费并获得奖励。
  - **驳回**：举报费不退；如果提交时奖励过积分，会收回。

  一条举报只能处理一次，两名管理员同时处理时只有一个生效。

角色、衣柜与举报的后台操作都会写入审计日志（`admin.player_*`、`admin.closet_*`、`admin.report_reviewed`）。

## 审计日志

`/admin/audit` 记录登录、注册、修改密码与邮箱、注销与恢复、后台对用户的修改和删除、后台对材质与角色的操作、举报处理，以及站点设置的变更：时间、操作者、对象、地址，以及改了哪些字段（角色、状态、积分、邮箱会记录修改前后的值）。在筛选框里输入动作名可以精确筛选，以 `.` 结尾表示前缀，例如 `admin.` 只看后台操作、`account.` 只看用户自己的账号变更。审计日志不会随用户删除而删除。
