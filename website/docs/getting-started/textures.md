# 皮肤库与材质

用户上传的皮肤与披风统称"材质"。公开材质出现在皮肤库 `/skinlib`，每个材质有自己的页面 `/skinlib/show/<编号>`（与 Blessing Skin 的地址相同，旧书签照样能打开）。上传的材质会自动放进上传者的衣柜 `/user/closet`；之后角色只能使用衣柜里的材质。

## 上传规则

| 类型 | 尺寸要求 |
|---|---|
| 经典皮肤（Steve） | 正方形（64×64、128×128……）或宽是高的两倍（旧版 64×32） |
| 纤细皮肤（Alex，手臂 3 像素宽） | 正方形 |
| 披风 | 宽是高的两倍（64×32……） |

- 只接受 PNG；宽度必须是 64 的倍数、高度是 32 的倍数。最大文件大小 `texture.max_size_kb`（默认 1024 KB），最大宽度 `texture.max_width`（默认 2048 像素）。
- 名称 1–50 个字符；可以用 `texture.name_regexp` 规定格式。
- 每个用户 10 分钟内最多上传 30 次（包括重复的图片）。
- 上传页会根据图片自动选择类型（披风、纤细或经典），可以手动修改。
- 服务器先读取图片头部确认尺寸，再解码整张图片，伪造尺寸的"解压炸弹"在解码前就会被拒绝。图片会被重新编码，其中的元数据（拍摄信息、文字注释等）不会保存下来。

## 积分

上传消耗的积分 = 文件大小（按重新压缩后的大小，每满或不满 1 KB 计 1 KB）× 单价 + `score.per_closet_item`，公开材质再减去奖励 `score.award_per_texture`：

| 设置 | 默认 | 说明 |
|---|---|---|
| `score.per_storage` | 1 | 公开材质每 KB 的积分 |
| `score.private_per_storage` | 10 | 私有材质每 KB 的积分 |
| `score.per_closet_item` | 0 | 每个衣柜条目的积分 |
| `score.award_per_texture` | 0 | 上传公开材质的奖励（私有材质没有奖励） |

积分不足时上传会被拒绝，不会扣分。每一次积分变化（注册赠送、上传、管理员修改）都记在积分流水里，包括变化后的余额；管理员修改还会记录是谁改的。积分的扣减是原子的，同时发出的多个请求也不会把积分扣成负数。

## 收藏与衣柜

- 在材质页点"收藏"，材质进入你的衣柜，消耗 `score.per_closet_item`；上传者（如果不是你自己）获得 `score.award_per_like`。同一个材质只能收藏一次。
- 在衣柜里可以给材质改一个自己看的名字（不影响材质本身），也可以移出衣柜：穿着它的角色会自动脱下，`score.return_on_delete` 开启时退还当初支付的积分，上传者的收藏奖励同时收回（上传者积分不够时不再收回，不会扣成负数）。
- 退还和收回都按积分流水里当初那一笔原样冲正，之后站点改了价格也不影响。

## 管理自己的材质

上传者和管理员在材质页的"管理材质"里可以：

- **改名**：遵守上传时的名称规则。
- **改类型**：按图片尺寸重新校验，例如方形的图不能改成披风。皮肤与披风之间切换时，正在穿它的角色会自动脱下；经典与纤细之间切换不影响角色。
- **设为私有 / 公开**：设为私有要补上私有与公开价格的差额（含公开上传的奖励），设为公开退还同样的差额，页面会提前显示数额。来回切换不会丢分（Blessing Skin 会，C12）。设为私有后，它会从其他人的衣柜和角色上移除，并退还他们的积分；同一张图已经有公开材质时不能设为公开。管理员修改别人的材质不收费，并记入审计日志。
- **删除**：收藏过它的人全部退费；上传者拿回这个材质在积分流水里的净支出（上传与公开性切换，扣除上传奖励）；穿着它的角色什么也不穿。不可撤销。

用户被永久删除时（管理员删除，或注销 30 天后），他的私有材质随之删除；公开材质保留，上传者显示为"已注销用户"。

## 举报

觉得某个材质有问题（盗用别人的作品、内容违规等），在材质页点"举报"，写下理由（最多 500 字）提交给管理员。只能举报自己看得见的材质，不能举报自己的；同一个材质只能举报一次，每人每小时最多举报 20 次。

- `score.reporter_modification` 小于 0 时，举报要先付这么多积分，举报成立（材质被删除或上传者被封禁）后退还，被驳回则不退；大于 0 时提交举报直接获得积分，被驳回时收回。
- 举报成立时另外获得 `score.reporter_reward`。
- 表单会提前显示这些数额。提交后在"我的举报" `/user/reports`（用户中心里也有入口）查看处理结果。

管理员如何处理见 [账号与用户管理](accounts.md#后台概览角色与举报)。

## 重复的图片

上传前会计算图片内容的哈希：

- 皮肤库里已有同样的公开材质，或者是你自己之前上传过的，直接跳转到那个材质，**不会重复上传，也不扣积分**。
- 别人私有的同一张图不算重复（你看不到它），会新建一个材质，但两者共用同一个文件。

文件按引用计数保存，只有不再被任何材质使用时才会删除，删除一个材质不会弄坏别人共用同一文件的材质（Blessing Skin 会，C06）。最后一个材质删除后，文件再保留 1 小时才清理，期间如果又有人上传了同一张图，文件会被继续使用；服务器每天还会清理一次没有任何记录的孤儿文件。访问页面时发现文件缺失不会删除材质记录（Blessing Skin 会，C10）。

## 公开与私有

- 皮肤库只列出公开材质。私有材质只有上传者和管理员能看到：上传者在自己的衣柜里找到它，管理员可以按上传者查看。
- 别人访问私有材质时返回 `texture.private_status`：默认 `403`；设为 `404` 则不透露材质存在。
- 皮肤库可以按类型（皮肤、经典、纤细、披风）筛选、按名称搜索，按"最新"或"最受欢迎"（收藏数）排序。排序方式是固定的白名单（Blessing Skin 可以按任意字段排序，包括用户邮箱，S07）。

## 文件地址

| 地址 | 说明 |
|---|---|
| `/textures/<哈希>`、`/csl/textures/<哈希>`、`/usm/textures/<哈希>` | 材质文件，供游戏客户端与预览使用。同一个哈希永远对应同一个文件，所以响应可以被浏览器和 CDN 永久缓存（`immutable`），支持 `ETag` 与断点续传 |
| `/raw/<编号>`（也接受 `/raw/<编号>.png`） | 原图下载，遵守公开/私有规则；`texture.allow_download = false` 时返回 403 |

## 头像与预览图

服务器把材质画成图片，供网页、论坛签名、启动器等直接引用（地址与 Blessing Skin 相同）：

| 地址 | 说明 |
|---|---|
| `/avatar/player/<角色名>` | 角色当前皮肤的头像；角色不存在返回 404，没有皮肤或主人被封禁时是灰色占位头像 |
| `/avatar/user/<用户 ID>` | 用户选择的头像（在衣柜里给皮肤点"设为头像"） |
| `/avatar/<材质编号>`、`/avatar/hash/<哈希>` | 某个皮肤的头像；披风返回 422 |
| `/preview/<材质编号>`、`/preview/hash/<哈希>` | 预览图：皮肤是正面和背面并排，披风是披风正面 |

- 参数：头像 `size`（16、24、32、48、64、96、100、128、256、512，默认 100），加 `3d` 得到立体的头；预览图 `height`（64、100、128、150、200、256、300、400、512，默认 200）。其它数值取最接近的一档。
- 默认输出 WebP（无损）；加 `png`，或客户端的 `Accept` 里没有 WebP 时输出 PNG。
- 画法与 Minecraft 一致：旧版 64×32 皮肤的左手左腿由右侧镜像得到，帽子层叠在头上，纤细皮肤的手臂是 3 像素宽；像素保持清晰，不会被插值模糊。
- 按哈希的地址可以被永久缓存；按角色、用户、编号的地址缓存 `delivery.profile_cache_seconds` 秒；私有材质只有上传者和管理员看得到，响应标记为 `private`，不会被 CDN 缓存。
- 材质页的链接预览（`og:image`）就是它的预览图，需要设置 `site.url`。

## 存储位置

材质文件默认保存在数据目录下的 `textures/`（`config.toml` 的 `[storage] path`），每个文件以内容的 SHA-256 命名。备份时连同数据库一起备份这个目录即可。也可以放进 S3 兼容的对象存储（阿里云 OSS、腾讯云 COS、七牛、MinIO、Cloudflare R2 等），并让 CDN 直接发送文件，见 [配置](configuration.md#对象存储s3-兼容)。
