## CSP 与自定义 JavaScript（ADR 0039）

- **每个页面请求生成一个随机 nonce。** 只有带 nonce 的脚本，以及由它们加载的脚本才能运行（`'strict-dynamic'`）。Next.js 自己的脚本、主题切换脚本和验证码脚本都走这条路。
  - 评论、材质名里如果混进了 `<script>` 或 `onerror=`，浏览器不会执行。
  - 页面只能被本站嵌入，表单只能提交到本站。
- **后端的回答带一个什么都不允许的策略。** JSON、图片、材质文件都不是页面，即使被当成页面打开也执行不了任何东西。
- **自定义 JavaScript。** BS 把它直接塞进页面，所以管理员账号被盗就等于全站存储型 XSS。SkinLoom 的做法和自定义 CSS 一样：
  - 只有超级管理员能改；
  - 作为单独的文件提供，由带 nonce 的 `<script>` 加载。

  它可以再加载统计代码之类的脚本。站点切换页面时不刷新，所以脚本在打开网站时运行一次；要改页面内容，就得监听页面变化。导入 BS 时，`custom_js` 也会带过来，报告里会说明这一点。
- **端到端验证。** 在构建好的站点上逐项确认：
  - 17 个脚本都带 nonce；
  - 注入的事件和外站 iframe 被拦下；
  - 三家验证码都能显示；
  - 3D 预览和皮肤库搜索正常。

## M4 的遗留问题

- **恢复时检查站点是否在运行。** 运行中的站点对 `data/skinloom.lock` 持有共享锁，`skinloom restore` 拿不到独占锁就拒绝，`--force` 也不行。锁由操作系统管理，进程崩溃时自动释放，不会出现"锁文件残留、什么都做不了"的情况。
- **Windows 上的私密文件。** 密钥、备份和日志只允许运行 SkinLoom 的账户、SYSTEM 和 Administrators 访问，不再继承上级目录的权限。Unix 上本来就是 0600 和 0700。
- **封禁会刷新 CDN。** 封禁、解封、注销、恢复、删除账号时，在同一个事务里为每个角色发出 `player.updated` 或 `player.deleted`。CDN 刷新本来就监听这两个事件。
- **翻译覆盖的完整校验。** 服务器端以前只检查花括号是否配对，现在按 ICU 消息格式完整解析。为了保证它和浏览器里 formatjs 的判断一致，我们用 formatjs 判定了两千多条文字（大部分是随机生成的），Go 的结果必须与它完全相同。前端自带的全部文字也必须通过。
