M3（外置登录与开放平台）四个部分都做完之后，进入 M4 之前把整个 M3 的代码重新看了一遍，跑了完整的回归和一次覆盖四个部分的端到端测试。发现并修了四个问题，没有发现需要回退的设计。

<!-- truncate -->

## 检查范围

约 9000 行非生成代码：Yggdrasil（令牌、加入服务器、材质上传）、OAuth 2.0 提供方（授权码、PKCE、刷新、吊销）、个人访问令牌、兼容 BS 的用户级与管理类接口、第三方登录，以及它们改动过的账号、举报、通知、角色代码。重点看鉴权、权限、令牌失效和跨站请求。

## 修了什么

- **封禁应用主人后，应用的令牌还能用到过期。** 封禁或注销应用主人时，应用不能再让人登录，但它已经签发给其他用户的访问令牌还能调用接口，最长 1 天。现在校验令牌时也检查应用主人的状态，解封后恢复。
- **跨域预检的范围太大。** 资源 API 允许任意来源调用，用一条 `/api/*` 的通配规则回应预检，结果 `/api/v1` 的预检也拿到了 `Access-Control-Allow-Origin: *`。浏览器其实仍会拒绝：允许的请求头里没有 `X-SkinLoom-Request`，也不允许带 Cookie。但 `/api/v1` 的 CSRF 防护靠的正是"别的网站永远得不到预检许可"，现在只剩这一层，改一行允许的请求头就会失守。预检改为只回应 BS 的几个路径，并加了回归测试，确保 `/api/v1` 和 Yggdrasil 接口永远不回应跨域预检。
- **`skinDomains` 里多了请求的 Host。** 设置了 `site.url` 时，Yggdrasil 元数据仍把请求里的 `Host` 加进允许加载皮肤的域名。响应不缓存，影响只限发请求的人，但没有理由信任它；现在只在没有 `site.url` 时使用请求的地址。
- **`/oauth/token` 的内部错误没有日志。** 数据库出错时只返回 `server_error`，服务端什么也没记。

## 子代理复查

之后又开了一个独立的子代理，从头审查了全部暂存的代码，并按 TDD 先写失败的测试再修。它没有发现鉴权绕过、CSRF / CORS 漏洞、开放重定向或账号接管，找到了两个真问题：

- **名称超过 64 字节返回 500。** 应用和个人访问令牌的名称在服务里按字符检查（最多 64 个），数据库字段却按字节限制，22 个以上汉字的名称通过了检查、写库时失败。改为按字符计（`users.nickname` 早就这样处理）。
- **极大的 `page` 溢出。** 兼容 BS 的分页接口计算偏移量时溢出成负数：SQLite 上回到第一页，PostgreSQL 上会报错。页码现在有上限。

它另外列了几条低风险的观察，其中三条也顺手修了：

- 没有密码的账号判断"最后一个绑定"时，把已从配置里删掉的提供方也算进去了，于是可能解除唯一还能用的绑定，把自己锁在外面；两个同时的解绑也可能都通过检查。现在只算还在配置里的提供方，并先锁住用户行再检查。
- 登录页的 `next` 可能是很长的授权地址，超过 512 字节时第三方登录直接失败；现在忽略过长的 `next`。
- `/api/admin/reports?q=status:9` 这样无效的筛选返回了全部举报；现在返回空列表，与 BS 一致。

没有修的一条：授权码被重复使用时，没有吊销用它换到的令牌（RFC 6749 建议这样做），刷新令牌也没有重放检测。授权码只能用一次、刷新令牌每次轮换，风险不大，记在这里，以后再看。

## 回归

- Go：`go test ./...`（SQLite 与 PostgreSQL）、vet、staticcheck、govulncheck；重新生成代码只有接口说明文字的变化，两种数据库都没有迁移漂移。
- 前端：类型检查、测试、构建、`bun audit`；文档站构建。
- 端到端：`skinloom up --dev` 加一个临时写的 OpenID Connect 提供方，用脚本走了 44 项检查：
  - Yggdrasil：元数据、邮箱和角色名登录、错误密码、刷新与旧令牌失效、上传纤细皮肤、加入服务器与 `hasJoined` 返回签名的材质、按名字查角色；
  - OAuth：授权跳转、同意、PKCE 换令牌、授权码只能用一次、`/api/user`、没有权限的写操作被拒、刷新；
  - 管理员个人访问令牌：查用户、封禁应用主人后应用令牌失效、解封后恢复、普通用户令牌调用管理接口被拒；
  - 跨域：`/api/v1` 不回应预检，`/api/user`、`/oauth/token` 回应；
  - 第三方登录：登录页显示提供方、回调、新账号、没有密码不能在启动器登录、回调不能重放、最后一个绑定不能解除、审计记录登录方式。

服务端日志没有警告或错误。

## 仍未验证

- 没有用真实的启动器（HMCL、PCL2）、真实的 BS 第三方应用或管理面板、真实的 GitHub / Microsoft / Google 应用实际接过，都是用程序和模拟的提供方测的。
- 后台还没有设置页面，社交登录和其它设置要用命令行或设置接口配置，这放到 M4。
