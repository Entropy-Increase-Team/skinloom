M4 第二部分做的是外观。后台多了"外观"页：切换主题、调颜色、编辑首页区块，再加上 Logo、页脚和自定义 CSS。为了让切换主题真的有得选，还加了第二套内置主题"织锦"。

## 先补主题标准里没兑现的部分

默认主题从 M0 起就写成了主题包，但清单里有几处前端从来没用过：`layout` 写了四项，一项都没生效（`user: sidebar` 描述的界面根本不存在）；`viewer` token 没有输出；设计文档列了 10 种首页区块，只做了 4 种。这次按 ADR 0030 补齐，并收紧了约定：

- **布局变体只列已经实现的**：登录页 `card` / `split`，皮肤库 `comfortable` / `compact`。清单里写了不认识的值，加载时报错，不再静默忽略。
- **区块目录放在后端**：每种区块的属性有类型（文字、Markdown、链接、图片、数字、选项、按钮）。`home.blocks` 和主题清单都按它检查，不安全的链接、未知的属性、超范围的数量都会被拒绝。后台编辑器也按这份目录生成表单，第二阶段插件声明的区块走同一套。
- **文字可以按语言分别写**：bootstrap 只给访客语言的那份，Markdown 在服务端渲染好，前端区块只读字符串。
- **新区块**：站点数据（读新接口 `/api/v1/site/stats`，缓存一分钟）、最新材质、热门材质、文字、图片、按钮组。

## 织锦

织锦是第二套内置主题：朱红与金色、分栏的登录页、更紧凑的皮肤库，首页带最新材质与站点数据。它把主题标准的 token、CSS、布局、首页四层都用了一遍，以后写第三方主题可以照着它。安装第三方主题仍在第二阶段。

## 外观页

- **主题**：列出已安装的主题，点"启用"立即切换；没有自定义首页时，首页也换成新主题自带的。
- **颜色**：亮色、暗色两组常用颜色和圆角，留空就用主题的值，可以用取色器（主题的 oklch 颜色会换算成取色器能显示的值）。含分号、花括号、尖括号或注释的值，以前保存后会在渲染时被悄悄丢掉，现在保存前就提示。
- **首页**：添加、排序、删除区块，按属性类型编辑；"改用主题自带的首页"把 `home.blocks` 设回空。
- **站点标识与页脚**：Logo、浏览器图标、页脚文字（Markdown）、搜索关键词。BS 的版权文字是 HTML，这里改成 Markdown，插不进脚本。
- **自定义 CSS**：对每个页面生效，所以只有超级管理员能改（BS S16），普通管理员看到的是只读。它不放进页面的 `<style>`，而是一个按内容哈希命名的单独样式表，写什么都破坏不了页面结构。自定义 JS 等加上 CSP 以后再做。

## 验证

- 新测试：区块目录的检查与按语言准备、两套内置主题的加载与布局、颜色覆盖的校验、自定义 CSS 的样式表与缓存头、只有超级管理员能改自定义 CSS、外观相关接口；前端的颜色覆盖、区块保存、分组顺序、布局变体。
- `go fmt`、`go vet`，完整的 `go test ./...`（SQLite 与 PostgreSQL）；前端类型检查、58 个单元测试与生产构建。
- 用 `skinloom up --dev` 起了整套服务，在浏览器里走了一遍：
  - 切到织锦，页面不重启就换了主题；未登录访客看到分栏登录页，首页显示站点数据，没有材质时最新材质区块不显示。
  - 不安全的颜色值不让保存；主色改成 `#336699` 后立即生效。
  - 首页加了文字区块和按钮组；按钮链接填 `javascript:` 时服务端拒绝并说明原因；改正后保存，英文访客看到英文的文字。
  - 设置 Logo、浏览器图标、页脚、关键词和自定义 CSS，页面上都对得上，自定义样式表能取到。
  - 普通管理员看到的自定义 CSS 是只读的，从接口改返回 403。
  - 改回主题自带的首页、清除颜色、切回默认主题，审计日志里每一步都有记录。

走查时发现并改了两处：站点标识一组里的字段按字母排序，Logo 排在最后；首页区块的错误信息从 0 开始数第几个。
