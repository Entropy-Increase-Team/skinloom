## 评审意见（来自项目负责人）
1. 前后端可以分离；Windows、macOS 发布时用脚本一键启动前后端或运行环境。
2. 前端用 Next.js，React 没有问题。
3. 插件要有自己的一套规则，不必兼容各种开发语言，但必须易于开发和学习、有统一标准，并开放足够的能力（含前端界面和主题）。
4. 插件/系统配置、插件安装卸载要支持热加载。
5. 项目需要一个名字，不能以 blessing 开头，鸣谢里保留 Blessing Skin。
6. 项目开发与插件开发都要有文档，包括开发日志、更新日志等长期维护的文档。

## 决策
- 插件后端引擎选 QuickJS-NG（WASM/wazero，ES2023、内存上限、超时），不选 goja（ES5.1 + 部分 ES6、无内存上限）。引擎藏在 `jsrt` 接口后，插件只依赖 SDK。
- 插件存储不开放 SQL：KV + 带索引槽位的文档集合 + 文件，三种数据库行为一致。
- 插件 UI 不参与 SSR；需要 SEO 的首页用"区块"（内置区块 SSR，插件区块客户端渲染）。

## 问题与风险
- fastschema/qjs 项目较年轻（约 600 star）→ 自有接口隔离，必要时自维护 QuickJS-NG 的 WASM 构建。
- macOS / Windows 未签名的可执行文件会被系统拦截 → 正式发行需要签名与公证（Apple 开发者账号；Windows 可考虑 SignPath 开源计划）。
- 第一阶段工期从 17–20 周调整为 19–21 周（新增启动器、Next.js 打包、主题标准化）。
