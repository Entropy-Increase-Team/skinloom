站点可以发邮件了：注册后验证邮箱，忘记密码时用邮件重置。为此先做了一个数据库任务队列，后面的里程碑也会用到它。

<!-- truncate -->

## 本期完成

- **任务队列**（`jobs` 表、`internal/jobs`）：业务写入与任务入队在同一事务里；每个节点都有 worker，提交后立即唤醒；条件更新 + 租约保证多副本只执行一次；退避重试；完成后清除 payload。
- **邮件**（`internal/mail`）：SMTP（TLS / STARTTLS / 明文本机中继，PLAIN / LOGIN）、开发用的 log 驱动、RFC 2047 头部编码、中英文纯文本 + HTML 模板、管理员测试邮件接口。
- **邮箱验证**：注册即发；链接 24 小时、一次性、需要点击确认；未验证提示条与重发（限流、旧链接作废）。
- **找回密码**：统一回答、验证码、按地址与邮箱限流、30 分钟一次性链接、重置后吊销全部会话、邮箱同时视为已验证。
- 前端：`/auth/forgot`、`/auth/reset/[token]`、`/auth/verify/[token]`，登录页"忘记密码？"，页头的未验证提示条。
- 设计记录：[ADR 0015 后台任务队列与邮件](https://github.com/Entropy-Increase-Team/skinloom/blob/main/docs/adr/0015-jobs-and-mail.md)。

## 本地实测（`skinloom up --dev`，log 邮件驱动）

1. 注册新账号 → 页面顶部出现"你的邮箱 … 还没有验证"；验证邮件在注册后的同一秒写入日志（提交后唤醒 worker 生效）。
2. 打开验证链接：此时接口仍显示未验证（只打开页面不会生效）；点击"确认验证邮箱"→"邮箱验证成功"，提示条消失。
3. 保持登录，在"找回密码"页提交邮箱 → 显示与账号是否存在无关的统一提示；日志里出现重置邮件。
4. 打开重置链接、设置新密码 → 成功；回到首页，本浏览器已被登出（`/me` 返回 401），页头显示"登录 / 注册"。
5. 用新密码登录成功，邮箱为已验证状态。服务端日志无警告、无错误。

## 测试

- 队列：执行、退避重试、彻底失败、`Permanent`、未知类型、payload 清除、事务回滚时任务一并消失、两个"节点"同时认领 20 个任务各执行一次、崩溃节点的租约到期后接手、7 天清理。SQLite 与 PostgreSQL。
- 邮件：MIME 结构与解码、中文发件人与标题、标题注入换行无法变成头部、HTML 转义、语言回退；用一个最小的假 SMTP 服务器测 PLAIN、LOGIN、收件人被拒、服务器不可达。
- 账号：重置（无邮件时报错、未注册邮箱同样成功且不发信、旧链接被新链接作废、短密码、重置后旧会话失效、旧密码失效、链接一次性、30 分钟过期）、限流（未注册邮箱同样计数）、邮箱验证（注册即发、重发限流、旧链接作废、一次性、已验证后不能重发）。SQLite 与 PostgreSQL。
- HTTP：找回与重置的完整流程、邮箱验证流程、管理员测试邮件（无驱动、log 驱动、SMTP 错误只给管理员）、bootstrap 的 `auth.mail`。

## 问题与风险

- SMTP 只用假服务器测过协议，没有对真实的 QQ / 163 / Gmail 发信。站长配置后请先用测试邮件接口确认。
- SMTP 密码与其它设置一样明文存在数据库里，只有管理员可见；加密的密钥存储计划在 M4。
- 时序：找回密码对已注册邮箱多做一次数据库写入，响应时间可能有毫秒级差异。
